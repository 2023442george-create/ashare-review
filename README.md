# 复盘罗盘 · 游资版（A股每日复盘工作台）

> 一个以短线复盘经验规则为基础的 A 股研究工作台：Python（FastAPI）+ Vue3 + ECharts。
> 核心是辅助回答三个问题：**今天市场情绪如何？哪些板块值得继续研究？哪些信号需要在后续交易中验证？**
> 全部数据来自**免费公开接口**，且每个数据点都配置了**多数据源自动备用**（主源挂了自动切换，前端会显示实际来源）。

## 一、30 秒启动

### 方式 A：一键脚本（推荐）

```powershell
# Windows PowerShell
cd ashare-review
.\scripts\start.ps1              # 正常启动（源码比产物新时自动重建前端）
.\scripts\start.ps1 -NoBuild     # 跳过前端构建，直接起服务
.\scripts\start.ps1 -Port 9000   # 指定端口
```

脚本会：检测 Python → 安装后端依赖 → 必要时重建前端 → 启动服务。

两条硬约束：**前端构建失败绝不会阻止服务启动**（界面旧只是难看，服务起不来会被误判成数据丢失）；
**端口不会被悄悄改掉**——`-Port` 优先，其次沿用已有的 `REVIEW_PORT`，最后才是 18080。

### 方式 B：手动

```bash
# 1) 后端（Python 3.10+）
cd backend
pip install -r requirements.txt
python run.py                      # 默认 http://127.0.0.1:18080

# 2) 前端（Node 18+）
cd ../frontend
npm install
npm run build                      # 产物输出到 backend/static，由后端直接托管
# 或者开发模式：npm run dev（5173 端口，自动代理 /api 到 18080）
```

打开 `http://127.0.0.1:18080` 即可。接口文档在 `http://127.0.0.1:18080/api/docs`。

> **默认端口 18080**（`run.py`、`scripts/start.ps1`、`scripts/start.sh` 一致）。
> 为什么不是 8000：Windows 的 Hyper-V/WSL 会不断把 1024–15000 里的随机区段划进
> 「TCP 排除端口范围」（`netsh int ipv4 show excludedportrange protocol=tcp`），
> 8000 和 8088 都已被吞过，绑定时报 `WinError 10013`，看起来像权限问题。
> 18080 在动态端口范围之外，不会被划走。
>
> 即使 18080 也被占用，`run.py` 会按候选列表（18081/18888/19090/28080/9090/8088/8080）
> 自动顺延，并**把实际地址打印在启动日志第一行**，以它为准。
> 想强制指定：`.\scripts\start.ps1 -Port 8080`，或 `set REVIEW_PORT=8080 && python backend\run.py`。

### 可选增强（不装也能跑）

```bash
pip install akshare      # 聚合几十个免费源，作为最后兜底
pip install adata baostock yfinance
```

## 三、多数据源备用设计（重点）

每个业务动作都是一条**源链**，按优先级依次尝试，第一个返回有效数据即采用，并记录 `meta.source`：

| 数据 | 主源 | 备用顺序 | 说明 |
|---|---|---|---|
| A股指数/个股行情 | 腾讯 `qt.gtimg.cn` | 新浪 `hq.sinajs.cn` → 东财 `push2/push2delay` → akshare → 内置样例 | 腾讯 HTTP 即可访问、最稳 |
| K线历史 | 腾讯 `web.ifzq.gtimg.cn` | 新浪 `quotes.sina.cn` → 东财 `push2his` → akshare | 东财K线自带成交额 |
| 涨停/炸板/跌停池、涨跌分布 | 东财 `push2ex` | akshare → 内置样例 | 复盘核心，东财独家口径 |
| 行业/概念板块、资金流 | 东财 `push2/push2delay clist` | 新浪板块 → akshare | 含主力净流入、涨跌家数、领涨股 |
| 龙虎榜+营业部席位 | 东财 `datacenter-web` | akshare | 含买卖席位、3日胜率 |
| 外围（美/日/韩/台/港/商品/汇率） | 东财全球指数 | 腾讯 → 新浪(gb_$ / int_ / hf_ / fx_) → Yahoo → Stooq | 逐资产 failover |
| 7×24 快讯 | 华尔街见闻 | 东财 → 新浪 → 财联社(带签名) | 并发拉取后聚合去重 |
| 两融/沪深港通 | 东财 `datacenter-web` | akshare | 北向实时净买入已停发，用成交额口径 |
| 指数估值 PE | 中证指数官网 `index-perf` | 蛋卷 `pe_history` | 官方滚动市盈率；PB/股息率只有蛋卷 |
| 中美国债收益率 | 东财 `datacenter-web` `RPTA_WEB_TREASURYYIELD` | 东财旧版 `datacenter` | 同一份数据的两个入口 |
| 宽基 ETF 份额 | 上交所 `commonQuery` | — | 暂不含深交所产品；首次接入请看 `/api/macro/probe` |
| 股指期货会员持仓 | 中金所 `sj/ccpm/*.csv` | — | 前20会员多空单，跨合约按会员汇总 |

额外三道保险：

1. **主机级熔断**：某域名连续失败 2 次会被跳过 4 分钟（例如某些网络下 `push2.eastmoney.com` 被限流但 `push2delay` 正常），避免每次白等重试。
2. **TTL 缓存 + 定时任务**：盘中每 2 分钟自动刷新，收盘 15:10 自动落库当日快照，21:00 补拉龙虎榜；历史情绪存 SQLite，形成情绪周期曲线。
3. **离线样例模式**：`REVIEW_OFFLINE=1` 时整套系统用内置样例数据运行（断网/内网/演示可用），前端不会白屏。

## 四·五、常见问题（Troubleshooting）

| 现象 | 原因与解决 |
|---|---|
| 跑完 `start.ps1` 整个应用打不开、像是数据全丢 | 检查脚本输出最后有没有 `== Server starting: ... ==` 这一行。没有就是启动前挂了（历史原因：npm 的 stderr 在 `$ErrorActionPreference="Stop"` 下会被升级成终止性错误）。现在构建失败已不会中断启动；急用时 `.\scripts\start.ps1 -NoBuild` 直接起服务，前端构建单独做 |
| `start.ps1` 报「一元运算符"!"后面缺少表达式」等语法错 | 脚本被以 ANSI/GBK 解码。本项目脚本已保存为 **UTF-8 with BOM**；若你自行编辑过，请用 VSCode/记事本另存为「UTF-8 with BOM」，或直接使用英文消息版本 |
| 端口 18080 被占用（WinError 10013 / address already in use） | `.\scripts\start.ps1 -Port 8080`，或 `set REVIEW_PORT=8080 && python backend\run.py` |
| 页面打开是空白/提示未连接后端 | 后端没启动或端口不对；确认 `python backend\run.py` 在运行，浏览器地址与 `REVIEW_PORT` 一致 |
| 某些指数/外围显示「—」 | 该资产所有源都不可用（如国内访问 Yahoo 被 403）。到「数据源设置」页看健康度，或挂代理后点「强制刷新」 |
| 新接口返回 `{"detail":"not found"}`、或新字段一直是空 | 跑着的后端进程比代码旧。`/api` 的 404 响应会自带 `likely_cause` 与 `fix`，`/api/health` 的 `backend.stale` 也会标出来。重启后端即可 |
| 板块榜单「涨/跌家数」显示「—」 | 上游接口没返回 f104/f105。界面会给出告警横幅和「探测字段」按钮；也可直接看 `GET /api/sectors/probe?kind=industry`，逐个东财镜像主机列出实际带回的字段。该列**不会**用 0 代替缺失 |
| 财联社资讯不可用 | 其接口需签名且经常变更，系统会自动降级到华尔街见闻/东财/新浪，不影响使用 |
| 想完全断网演示 | `.\scripts\start.ps1 -Offline`（内置样例数据） |
| 页面顶部红条「节假日表缺少 XXXX 年」 | `backend/app/core/utils.py` 的 `CN_HOLIDAYS` 只维护到某一年。国务院一般在 11~12 月公布次年休市安排，把休市日期补进去即可；不补的话节假日会被当成交易日 |
| 首次启动很慢 | 正常：要拉取涨停池/龙虎榜/板块/外围等约 20 个接口；之后命中缓存秒开 |

## 研究方法与验证边界（重要）

本项目的情绪评分、主线识别、候选股排名和仓位提示属于**经验规则输出**，不是已经证明有效的交易策略。
`data_quality.level = complete` 只说明输入数据通过了现有检查，与策略是否赚钱无关；分数高只是规则排序，不是上涨概率。

与一般"加一句免责声明"的做法不同，这些边界在本项目里是**算出来的**，不是写死的：

| 机制 | 在哪 | 作用 |
|---|---|---|
| **结果账本** | `services/track.py`、`signal_log`/`signal_outcome` 表 | 收盘后冻结当日**全部可选标的**（含未选中，供置换检验做零分布），带真实冻结时间戳与参数指纹；次日及以后按"次日开盘入场 / T+N 收盘出场"回填结果，扣费后减同期基准 |
| **前视偏差守卫** | `tests/test_ledger_and_leakage.py` | 断言入场价必须来自候选日**次一**交易日开盘。改成候选日收盘价会让所有策略"收益"凭空变好，这条测试会立刻失败 |
| **可成交性** | `regime.is_limit_up_price` | 次日开盘即一字封死的样本标为不可成交，从统计正文剔除并单独报告比例。买不到的收益不是收益 |
| **分层置换检验** | `services/validate.py` | 把"规则选出的票"换成"同日同一可选池随机抽同样多只"重复上万次。只需当天横截面，不需要历史面板，所以今天就能跑 |
| **样本量门槛 + 区间** | `params.STATS.min_sample` | 样本不足 30 的因子退回中性分；所有收益都报 n、中位数、Bootstrap 95% 区间 |
| **参数扰动区间** | `sentiment.score_band` | 阈值与权重整体扰动 ±20% 后重算分数。区间宽度大于两日分差时，日间比较自动失效 |
| **数据对账** | `services/reconcile.py` | 两条独立路径（涨停池接口 vs 涨跌分布第 11 档 vs 按涨跌幅制度表自行判定）互相比对 + 不变量检查。不变量失败直接禁用决策 |
| **涨跌幅制度表** | `core/regime.py` | 按"代码 + 日期"查当日档位（创业板 2020-08-24 由 10% 改 20% 等）。口径未知返回 `None`，不退回默认 10% |
| **多重检验校正** | `/api/track/matrix` | 4 策略 × 4 持有期 = 16 次检验必然出现一个 p<0.05，用 BH 校正后才算发现 |
| **验证状态** | `/api/track/status` | 由账本统计算出，`validated` 字段恒为 `false`，并列出推进一步需要什么 |

**系统刻意没有"已验证"状态。** 样本内未被否证不等于有效，还需要预注册的 holdout、独立第三方复现，
以及真实或模拟成交记录的印证——这些事情代码无法代替人完成。

### 账本怎么攒

前瞻样本只能从今天开始攒，每拖一天就永久少一天。收盘定时任务（15:14）会自动做这两件事；也可手动：

```bash
curl -X POST "http://127.0.0.1:18080/api/track/freeze"    # 收盘后冻结今日信号
curl -X POST "http://127.0.0.1:18080/api/track/settle"    # 次日及以后回填前瞻结果
curl "http://127.0.0.1:18080/api/track/record?strategy=first_board&horizon=1"
```

或直接打开「证据与验证」页，三个按钮都在上面。**账本断档就是断档——不要事后补冻结**，
补出来的样本是用今天的信息选的。

```bash
python -m unittest discover -s tests -v     # 项目根目录执行，不访问网络
```

测试只验证确定性代码行为（口径、不变量、前视偏差守卫、统计工具本身是否可信），**不验证盈利能力**。
