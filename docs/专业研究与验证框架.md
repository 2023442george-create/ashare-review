# 证据与验证：已实现 / 未实现 / 如何复核

版本：`params-2026.10-r2` / `track-v1`　
本文件是**审计清单**，不是计划书。每一条都写明它现在落在代码的哪里、怎么自己验一遍、以及它**不能**证明什么。

> 旧版本这份文档描述的是"专业团队应该做什么"。那种写法的问题是：文档越完整，越容易让人以为事情已经做了。
> 本版只记录可执行的东西——能跑的命令、能打开的接口、能失败的测试。做不到的部分单列在第 4 节，不混进正文。

---

## 1. 两个必须分开的命题

| 命题 | 能否被证明 | 证据来源 |
|---|---|---|
| **A. 算得对** | 能 | 跨接口对账、按涨跌幅制度表独立判定、不变量测试、固定种子复算 |
| **B. 策略有效** | **不能** | 只能处于「在某个区间、某套成本假设下尚未被否证」的状态 |

把两者混为一谈是这个领域最常见的错误。本项目的 `data_quality.level = complete` 只说明**输入数据通过了现有检查**，
它和策略赚不赚钱没有任何关系；`composite.score` 高只是规则排序，不是上涨概率。

系统刻意**没有**"已验证"这个状态值：`/api/track/status` 的 `validated` 字段恒为 `false`，
并在 `what_would_change_this` 里列出需要什么才能推进一步。这不是谦虚，是因为代码无法替人完成预注册与独立复现。

## 2. 命题 A：算得对——已实现，可自行复核

### 2.1 两条独立路径对账（而非多源 failover）

`cache.chain` 是 failover：按优先级试源，第一个通过校验的就采用。它解决"有没有数"，从不回答"数对不对"。
`services/reconcile.py` 做的是对账：

| 路径 | 实现 |
|---|---|
| 1 | 东财 `push2ex` 涨停池家数 |
| 2 | 东财涨跌幅分布接口第 11 档家数（不同接口、不同计算链路） |
| 3 | 按 `core/regime.py` 的涨跌幅制度表，从收盘价/前收盘价**自行判定**是否封在涨停价 |

两条独立实现同时错到同一个数的概率极低，所以一致性是正确性的实证依据；不一致则必然至少有一方错。
**本模块只报告差异，从不自动对齐**——被静默修好的问题比暴露出来的 2% 偏差危险得多。

复核：`GET /api/reconcile`，或打开「证据与验证」页。不一致样本会逐只列出收盘价、涨幅、按制度表应有的涨停价。

### 2.2 涨跌幅制度表（`core/regime.py`）

"涨停"不是固定定义。创业板 2020-08-24 之前 10%、之后 20%；科创板 20%；北交所 30%；主板风险警示股 5%；
新股上市头几日不设限制。不按「代码 + 日期」查当日档位，而统一按 10% 判定，会让创业板/科创板的票整体错判，
并让跨 2020-08-24 的任何序列混用两种口径。

- 口径未知时返回 `None` 而不是退回默认 10%——退回默认值就是制造静默错误。
- 该表**人工维护**，可能滞后于公告，因此 `regime_note()` 自带 `maintained_by: human` 警告，
  且对账发现冲突时以实际行情为准并报告差异，不以表为准。
- 统计口径变更时间线（含北向实时净买入 2024 年 8 月中旬停止披露）：`GET /api/research/regime`。

### 2.3 不变量测试

不依赖任何外部数据的硬约束，违反即说明代码或口径有 bug：

- 炸板率 ∈ [0,100]；封板率 + 炸板率 = 100
- 天梯各层家数之和 = 涨停池总数
- 连板数 + 首板数 ≤ 涨停池总数；最高连板 = 天梯最高层
- 可成交样本数 ≤ 总样本数

**不变量失败直接禁用决策**（`report.apply_reconcile_gate`）：算错比缺数严重，因为缺数看得见。
跨源不一致只降级为警告，因为它可能只是口径差异（是否含北交所/ST/新股）。

### 2.4 参数指纹与确定性复算

`core/params.py` 是所有阈值、权重、成本、统计设置的唯一来源，`digest()` 给出规范化 JSON 的 sha256 前 12 位。
该指纹写入每一条冻结的信号记录，于是"当时用的是不是这组参数"可以被验证，而不是靠记忆。
统计用固定随机种子（`STATS.seed`），同一输入必须复算出同一 p 值与同一 Bootstrap 区间。

复核：`GET /api/research/params` 看参数与指纹；`GET /api/track/signals` 看每条信号携带的指纹与冻结时间戳。

### 2.5 回归测试

```bash
python -m unittest discover -s tests -v      # 项目根目录执行；不访问网络
```

测试只验证确定性代码行为，**不验证盈利能力**。覆盖：

- 参数指纹的确定性与"改阈值必须改指纹"
- 涨跌幅制度表的跨日期切换、ST 档位、未知板块不得默认 10%
- 置换检验在**构造的零假设世界**里必须不显著（尺子本身可信）
- "日期效应"反例：每天全选、只是日期波动大 → 必须不显著（验证分层实现没把普涨日的收益当成能力）
- 入场价必须来自候选日**次一**交易日开盘（前视偏差守卫）
- 开盘一字封死样本必须标为不可成交并从正文剔除
- `ret_net = 毛收益 - 来回成本`、`excess = 扣费后 - 同期基准`
- 构造"评分与收益无关"的世界 → 汇总必须报 `no_evidence`
- 情绪分不得使用昨涨停**收盘**溢价（见 3.1），小样本溢价不得摆动分数

## 3. 命题 B：策略有效——已搭好机器，证据靠时间积累

### 3.1 已修掉的一个真实口径泄漏

旧版情绪分的溢价因子用 `prev_premium`：昨日涨停股今日的**收盘涨跌幅**。
那个价格对一只今天一字板封死的票是全天都拿不到的，用它当"打板次日收益"会系统性高估赚钱效应，
而且在一字板密集的强势行情里高估得最厉害——恰好是最该谨慎的时候。

现在评分使用 `tradable_premium`：只统计今日开盘确实可买入的样本（剔除开盘即封死），从开盘价算到收盘价。
收盘口径降级为参考值，界面与报告都标注"含买不到的样本，不参与评分"。
`score_components` **刻意不做回退**（不写 `tradable or prev`），因为静默回退等于把刚修掉的泄漏放回去；
`tests/test_research_safety.py` 为此留了专门的回归测试。

### 3.2 样本量门槛与不确定区间

- 昨涨停只有 9 只时，"平均溢价 6.1%"可以由一只票决定。低于 `STATS.min_sample`（默认 30）的因子
  退回中性分并标 `low_confidence`，同时进入数据体检警告。
- 所有收益统计都报 n、中位数、四分位、胜率与 **Bootstrap 95% 区间**。
  「均值 3.2%」与「均值 3.2%，95% 区间 [-1.8%, 8.4%]」是完全不同的两个结论。
- 情绪分与综合分都输出**参数扰动区间**：把全部阈值与权重同时扰动 ±20% 再重算。
  若区间宽度大于两日分差，"今天 62 分比昨天 59 分好"这句话自动失效。

### 3.3 结果账本（`services/track.py`）——整个研究体系的地基

一个每天产出候选股、却从不记录候选股后来怎么样的系统，不管界面做得多好，都没有产生任何可被检验的东西。
前瞻样本有三个性质决定了它必须最先建立：**免费**（每天写一行即可）、**无法事后篡改**（冻结时间戳 + 参数指纹）、
**不能补**（历史行情能买，但"当时这套规则会选哪些票"永远无法重建，因为板块成分、主线判定、龙虎榜披露状态都已改变）。

| 动作 | 时点 | 做什么 |
|---|---|---|
| `freeze` | 收盘后（定时 15:14） | 冻结当日**全部可选标的**并标记选中与否 |
| `settle` | 次日及以后（定时 15:14） | 次日开盘入场、T+N 收盘出场，扣费后减同期基准 |
| `record` | 随时 | 汇总成带样本量、区间、p 值、不可成交率的战绩表 |

三个刻意的设计选择：

1. **未选中的标的也要存。** 置换检验需要"决策时点真实可选的全集"做零分布；只存选中的票就永远无法回答
   "规则是否优于在同一池里乱选"。
2. **入场价固定为次日开盘。** 候选日收盘价是做决策时已知的价格，但那一刻市场已关门。用它算收益是最常见的前视偏差。
3. **基准是国证 2000，不是上证指数。** 权重股和游资票不是一个风险敞口，拿上证做基准会系统性高估短线策略。
   毛收益在短线票上几乎总是正的（小盘 beta + 普涨），所以战绩表报的是**扣费后超额**。

成本模型（`params.COST`）：佣金双边、过户费双边、印花税卖出、滑点双边，合计约 0.70%/来回，可整体做压力测试。

### 3.4 分层置换检验

要回答"规则是否优于乱选"，必须先知道"乱选会是什么样"。参数检验要先假设分布；置换检验直接把标签打乱上万次，
构造零假设下的经验分布。**关键优势是只需要当天的横截面，不需要历史面板**——所以在快照还没攒够时，
它是唯一能立刻产出真统计量的工具。

必须**按交易日分层**：如果把所有天混在一个池子里置换，等于允许"从大涨那天抽票、和小跌那天的实际持仓比较"，
日期效应会凭空造出显著性。分层置换在每一天各自的可选池内部重抽同样多的票，日期效应在零分布与观测值里同等抵消。
（与临床试验按中心分层随机化同一思路。）

p 值用 `(hits+1)/(iters+1)` 平滑，因为 p = 0 是不可能的结论。

### 3.5 分层单调性与多重检验

- **评分分 5 档看超额是否单调上升。** 均值可以被少数样本操纵，但整齐的 5 档阶梯很难偶然制造。
  只有最高档高，通常意味着少数极端样本而不是排序能力。
- **BH 校正。** 同时看 4 策略 × 4 持有期 = 16 个检验，必然会有一个 p<0.05。
  `/api/track/matrix` 对全部 p 值做 Benjamini-Hochberg 校正，只有校正后仍 ≤0.05 的格子才算发现。
  `research_trial` 表记录试错台账——多重检验校正需要这个分母。

### 3.6 因子有效自由度

涨停家数、最高连板、晋级率、上涨家数占比在 A 股里高度同向。七个因子配七档权重看起来精密，
但若相关矩阵特征值的参与率只有 1.x，那么调权重调的是噪音。
`sentiment.core` 用已落库的历史情绪快照算出有效自由度并给出判读（<2.5 判为"加权细调属于伪精度"）。
历史不足时如实返回"样本不足"，而不是给一个好看的数字。

## 4. 未实现：当前数据条件下做不到的部分

这一节不写"计划"，只写**缺什么素材、因此哪些问题现在不能回答**。

| 缺口 | 导致不能做什么 | 最低补齐条件 |
|---|---|---|
| point-in-time 股票状态表（上市日、ST 变更日、退市日） | 无法排除幸存者偏差：今天退市的票在历史涨停池里已经消失 | 每日存一份全市场状态快照 |
| 历史行业/概念成分的**生效日期** | 无法做主线/板块回测。用今天的成分回测过去是最隐蔽的致命 bug——相当于把"后来才被归进该概念的强势股"塞回历史 | 每日存一份成分快照（本项目尚未做） |
| 龙虎榜交易日 / 披露日双时间戳 | 无法保证席位信号不穿越：T 日龙虎榜 T 日晚才披露，用它做 T 日决策即是穿越 | 两个字段分开存储 |
| 分钟级公告/新闻发布时间 | 无法做催化研究：只有日期无法判断信号在决策时点是否已可见 | 保存原始时间戳而非日期 |
| 集合竞价逐笔量、封单撤单明细 | 只能用"开盘是否封死"近似可成交性，无法估计实际成交概率 | 需要分笔数据 |
| 交易所官方日报 | 对账只在免费接口之间进行，无法声称"对权威口径无偏差" | 取交易所日报做第三方基准 |
| 预注册的 holdout 区间 | 无法把"样本内未被否证"升级为"有证据" | 划定一段数据，一辈子只测一次 |
| 真实或模拟成交记录（含未成交） | 无法印证可成交性假设 | 需要用户自己记录 |

另外两点如实说明：

- **复权口径。** 日线用前复权。入场与出场在同一次拉取内，复权基准一致，收益计算正确；但若区间内除权，
  涨停价判定可能偏差。这一点写在 `settle()` 返回的 `method.price_basis` 里，不藏在代码注释。
- **历史模式的限制。** 非最近交易日的查询会禁用需要逐股实时行情的指标（`limitup.history_depth_ok`），
  历史报告只读已冻结快照（`report.build` 对缺快照的历史日期抛 409），断板反包、主线归属在历史模式下直接返回空。
  这些都是为了避免用今天的行情回填过去，宁可缺失。

## 5. 第三方如何复核

交给独立复核者的最小集合：

1. `GET /api/research/params` —— 参数全文 + 指纹（先确认用的是哪组参数）
2. `GET /api/track/signals?date=YYYY-MM-DD` —— 该日冻结的全部记录，含冻结时间戳与参数指纹
3. `GET /api/track/record?strategy=&horizon=` —— 战绩表，含 n、区间、p 值、不可成交率
4. `GET /api/reconcile?date=YYYY-MM-DD` —— 两条独立路径的差异与不变量结果
5. `GET /api/research/regime` —— 当日适用的涨跌幅档位与口径变更时间线
6. `python -m unittest discover -s tests` —— 不访问网络，应全绿
7. `data/review.db` 的 `signal_log` / `signal_outcome` 表 —— 原始账本

可验证的结论是："在同一账本与同一参数指纹下，复核者得到同一组统计量。"
**不可由此得出**的结论是："这套规则能持续盈利。"后者需要长期样本外证据，两者不可混为一谈。

## 6. 如何不自欺

- 不要先看结果再调阈值。要调就把 `PARAM_VERSION` 加一，账本里会出现两个指纹，系统会提示该段样本不可合并解读。
- 不要只展示最优的一段行情。战绩表给的是整段覆盖区间。
- 不要把"数据体检完整"读成"策略有效"。它们在报告里是两行，刻意分开。
- 不要把毛收益当战绩。短线票的毛收益几乎总是正的。
- 不要用单日 p 值做判断。单日样本太小，p 值几乎永远不显著；按日累计后看 p 值序列是否整体左偏。
- 账本断档就是断档。不要事后补冻结——补出来的样本是用今天的信息选的。
